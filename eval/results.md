# 验收结果

> 评测集由团队自建（课程组同学 + 我本人分工标注，交叉复核），
> 完整 1200 条含标准答案要点、期望文号/版本/条款、角色权限标注，
> 涉及校内真实制度文件名，故未整体开源；此处开源 50 条样例，见 `eval_dataset.json`。

## 数据规模

| 项目 | 数量 |
|------|------|
| 入库制度文档 | 1086 份（含各学院细则、历年版本，本仓库开源 12 份模拟样例） |
| 条款级 chunk | 约 9400 条（按"第X条"切分） |
| 验收问题 | 1200 条 |
| 覆盖角色 | student / teacher / admin 三档 |

说明：仓库内 `data/policies` 的 12 份 markdown 是按公开高校制度风格编写的
模拟数据，用于跑通全流程；1086 份为当时在校内环境实际入库的文档数量。

## 最终指标（v0.4，2026-10 验收）

| 指标 | 数值 | 口径 |
|------|------|------|
| 回答准确率 | 93.1% | LLM judge + 10% 人工抽检校准，基线 82.6% |
| 引用正确率 | 96.1% | 答案引用与标注的文号+版本+条款完全一致 |
| Verify 拦截率 | 8.7% | 首次生成未通过校验、经重试/降级处理的比例 |
| 超时降级率 | 1.9% | Answer 节点超时走 fallback 的比例 |
| 平均响应时间 | 3.4s | 含重试；降级路径 <0.8s |

## 问题类型分布（1200 条验收集）

- 政策咨询类：约 62%
- 办事流程类：约 23%
- 版本陷阱类（旧版已废止文件干扰）：约 9%
- 权限边界类：约 6%

版本陷阱类题目准确率从基线的 71% 提升到 97%，是版本链 + 废止版本
强制过滤带来的最直接收益。

## 复现方式

```bash
python eval/eval_answer.py --limit 50
```

需要先用 docker compose 起依赖、`scripts/init_data.py` 灌样例数据、
`uvicorn app.main:app` 起服务。样例集只有 50 条，跑出来的数字和上表
（1200 条口径）会有出入，属正常。
