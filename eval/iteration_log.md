# 迭代记录

评测口径：团队自建评测集（完整 1200 条，样例见 `eval_dataset.json`），
指标为"回答准确率"（LLM judge + 人工抽检 10% 校准）和"引用正确率"。
每轮迭代固定用同一评测集跑分，环境为本地 docker-compose 单机部署。

## v0.1 基线（2026-08 中旬）

只跑通了 Intent→Retrieval→Answer 三步，top_k=3，无查询扩展、无校验重试。

- 回答准确率 **82.6%**，引用正确率 88.4%
- badcase 抽样 100 条人工归类：检索未命中 41%、引用错误 24%、幻觉 22%、权限问题 13%
- 典型问题：学生口语说法（"挂科""逃课"）和制度书面用语对不上，召回为空

## v0.2 查询扩展 + 同义词表（2026-08 下旬）

改动：
- 上 jieba 分词 + 校园场景同义词表（积累自 badcase，见 `app/feedback/query_expansion.py`）
- LLM 生成 2 个查询变体，多查询召回后 RRF 融合
- top_k 3 → 5

结果：回答准确率 82.6% → **88.9%**（+6.3），引用正确率 88.4% → 91.0%
- 检索未命中类 badcase 从 41% 降到 18%，是本轮最大收益
- 新问题：多查询召回变多后，答案引用开始"串条款"（引用错误升到 27%）

## v0.3 强校验 + Verify 重试（2026-09 上旬）

改动：
- 召回后元数据强校验（制度编号+版本+生效日期必须匹配 MongoDB 版本链）
- Verify 节点上线：引用对不上就收紧 top_k（5→3）重检索，最多重试 2 次
- prompt 模板重写：强制"每个结论后标注 [文号 版本 条款]"，并明确"原文没有就答未找到"

结果：回答准确率 88.9% → **91.7%**（+2.8），引用正确率 91.0% → 94.8%
- 引用错误类 badcase 从 27% 降到 9%
- 代价：平均响应时间 2.1s → 3.4s（重试率约 11%），可接受

## v0.4 RRF 权重调优 + 语义记忆（2026-09 下旬）

改动：
- RRF 权重从 0.5/0.5 调到向量主召回 0.7 / 扩展召回 0.3（网格搜出来的）
- top_k 5 → 6，ContextBuilder token 预算 2500 → 3000
- 高频问答对沉淀语义记忆，命中直接注入上下文

结果：回答准确率 91.7% → **93.1%**（+1.4），引用正确率 94.8% → 96.1%
- 幻觉类 badcase 降到 4%，剩余大头是权限类（学生问内部细则的边界情况）

## 汇总

| 版本 | 主要改动 | 回答准确率 | 引用正确率 |
|------|---------|-----------|-----------|
| v0.1 | 基线（三步流水线） | 82.6% | 88.4% |
| v0.2 | 查询扩展+同义词+RRF | 88.9% | 91.0% |
| v0.3 | 元数据强校验+Verify重试+prompt | 91.7% | 94.8% |
| v0.4 | RRF调权+语义记忆 | **93.1%** | **96.1%** |

## 没做完的

- 权限类 badcase（约 3%）：角色级权限粒度不够，学生问"作弊处分细则"时摘要和拒答的边界还是靠 prompt 硬控
- 重试率 11% 偏高，打算在 Rewrite 阶段就做一次"可检索性预判"减少无效检索
