# 权限设计说明

## 角色

| 角色 | 说明 |
|------|------|
| student | 普通学生，能查绝大多数制度全文 |
| teacher | 教职工（含辅导员），可额外查看敏感制度的内部细则 |
| admin | 管理人员（教务处/学工处/网络中心等），全部可见 |

角色由 `POST /api/ask` 的 `role` 参数传入。说明：这是简历项目的简化
实现，真实系统里 role 应来自统一身份认证（对接学校 CAS/OAuth），
而不是客户端自报——这点在 README 的"已知不足"里也写了。

## 文档级权限

大部分制度三种角色都可见全文。敏感制度按 doc_id 配置在
`app/rag/retriever.py` 的 `PERMISSION_MAP`：

| doc_id | 制度 | student | teacher/admin |
|--------|------|---------|---------------|
| ks-wg | 考试违规处理办法 | 摘要（截断到【内部细则】标记前） | 全文 |
| wlaq | 校园网络安全管理规定 | 摘要 | 全文 |
| 其他 | 奖学金/请假/宿舍/转专业等 | 全文 | 全文 |

例：student 问"作弊情节认定的内部细则"，检索到的第七条 chunk 会被
`_summarize_for_student` 截断，只返回前半段 + "详细处理细则仅教职工
可见，如需了解请联系辅导员"；teacher 问同一问题能拿到完整条款。

## 截断机制

敏感制度原文里用 `【内部细则】` 标记分隔"对外部分"和"内部掌握部分"
（见 `data/policies/06_考试违规处理办法_v2.md` 第七条）。截断在两处兜底：

1. `retriever.py`：召回后按角色截断 chunk 文本
2. `context_builder.py`：组装 prompt 前再兜一层，防止有 chunk 绕过检索层

## 版本可见性

废止版本（status=revoked）默认不参与召回，但 admin 溯源场景可以通过
版本链 API 查询任意日期的生效版本（`get_effective_version`），
用于回答"2024年9月时这个政策是怎么规定的"这类问题。

## 已知边界

- 只做了角色级（文档级）权限，没做字段级：比如奖学金金额对三种角色
  都可见，但现实中可能有"仅学院评审委员可见的评议过程数据"
- role 参数未做鉴权校验，属于演示性质
- 权限拒答的边界靠 prompt + 截断硬控，评测里权限类 badcase 仍占约 3%
